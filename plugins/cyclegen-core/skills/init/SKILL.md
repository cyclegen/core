# CycleGen init（プロジェクト初期化）

> このスキルは **明示起動専用**。明示指定で呼ぶ（Claude Code: `/cyclegen-core:init` ／ Codex: `$init`）。
> ※ Codexの呼び出し名は frontmatter `name: init` に一致する（配置dir名ではない）。`$cyclegen-init` では起動しない（CYCLE14.21 finding#2）。
> コマンドの実体は **AIへの指示文**。init自身がファイルを作るのではなく、本文の手順に従って **AIが Write / Bash で生成**する。
> プロトコル本文（PDCA・記憶運用・思考法）は Skill が定義する。init は**利用者環境への配置と層2の生成**だけを担う（製品コアの再定義はしない）。

> **⚠ initは作業CYCLEではない（承認ゲート非適用）**: initはセットアップ・初期化であって作業CYCLEではない。**CYCLE番号を持たず、ダイジェスト/承認ゲート（Do→Check→Action）を適用しない**。CYCLE0ダイジェストや `_承認前` を作らず、初期化が終わったら**完了報告のみで終える**。実作業CYCLEはCYCLE1から始まる。毎ターン注入される常時規律（承認ゲート）をinitに適用しないこと（CYCLE14.25 finding F1 / FR039）。

## 何を生成するか

| 生成物 | 内容 | 出典 |
|--------|------|------|
| 標準ディレクトリ構造 | 日英＋番号体系（01-09 / 10-19 / 90-99）＋ `_template_` ひな型 | Skill `cyclegen-cycle`「標準ディレクトリ構造」（**製品が定義、initが配置**） |
| 薄い利用者 `CLAUDE.md`（Codex等は `AGENTS.md`） | 人格名・応答言語/トーン・プロジェクト目的/スコープ・プロジェクト状態セクション ＋ **常時規律4ブロックの要点（層2）** ＋ **CYCLE開始チェックリスト（memory_search含む）** | 下記§層2の派生生成／§CYCLE開始チェックリスト ／ 人格雛形 `agents/cyclegen-persona.md` |

## 対話フロー（init実行時）

1. **言語を確認**: 日本語 / 英語 を尋ねる（引数で `ja` / `en` が渡っていればそれを使う）。
2. **ディレクトリ構造を生成**: Skill `cyclegen-cycle`「標準ディレクトリ構造」に従い、確認した言語のツリーを `Bash`（`mkdir -p`）で作成する。番号体系（01-09 管理・計画系 / 10-19 アウトプット系 / 90-99 運用・メタ系）とひな型ファイル（`FR_INDEX.md` / `_template_FR.md` / `_template_ダイジェスト.md`）も配置する。
3. **人格を確認**: `{{AI_NAME}}`（AIの呼び名）／`{{USER_NAME}}`（利用者の呼び名）を尋ねる。`agents/cyclegen-persona.md` の雛形を読み、プレースホルダを置換して利用者ファイルへ反映する（デフォルト人格は同梱しない＝命名は利用者が行う）。
4. **薄い利用者 CLAUDE.md / AGENTS.md を生成**: §層2の派生生成 に従って本文を書き出す。
5. **既存ファイル保護**: 生成先に既存ファイルがあれば**上書きしない**。差分を提示し、利用者の承認を得てから反映する（破壊防止）。
6. **完了報告（承認ゲートは通さない）**: 生成物を一覧で提示して終える。その**末尾に、次の1行を必ず添える**:
   > 「準備ができました。次は最初の3サイクルを一緒に回しましょう。次をそのまま入力してください:
   > 　Claude Code : **`/cyclegen-core:onboarding`**
   > 　Codex       : **`$onboarding`**」

   > **★ホストごとの記法を対等に並べる（M-26／CYCLE17.6.6）**: 片方を主・片方を括弧の中にすると、**そのホストの利用者は自分では打てないコマンドを最初に読むことになる**。面A（Mac×Codex）・面C（Windows×Codex）の**両方で再現＝OS非依存**。**正本の型は `onboarding/SKILL.md` のリセット案内（Claude Code / Codex を2行で並べる形）**——そちらに合わせてある。

   > **★この1行を落とさない。** initが終わった利用者は**空のディレクトリと空の記憶ストアの前に置き去りにされる**。CycleGenの価値（蓄積の複利）は空ストアでは原理的に体感できないため、次の一歩を明示的に手渡す必要がある。**引き継ぎであって、initがサイクル0を実行するのではない**（initは配置作業のまま・上の⚠は変わらない）。詳細は Skill `onboarding`。

## 層2の派生生成（正本=primerから機械生成・手で書かない）

利用者 `CLAUDE.md` / `AGENTS.md`（層2）には「常時規律」セクションを置く。この本文は **手で書かず、正本から派生生成**する。

> **層2に書く4ブロックの実体は、直下（このSKILL.md本文の下記コードブロック）に埋め込み済み**。init 実行時に外部ファイルを読む必要はない（**実行時依存ゼロ**＝Codex等で `No such file` を出さない。CYCLE14.21 finding#3 / CYCLE14.24 修正）。
> **ビルド時の正本（single source）= `hooks/remind-primer.sh` の案B 4ブロック**（CYCLE14.3確定）。プライマー文言を変えたら、配布物ビルド時にこの本文へ反映する（実行時ではなくビルド時に同期）。
> 根拠: 「同じ規律を複数層で二重化する時は single source を1つ決め他は同期させる」（CYCLE14.3・L5）。実行時到達性を優先し、正本参照はビルド時に切り離した。

生成する「常時規律」4ブロック（正本の要点）:

```
## 常時規律（CycleGen）
- 承認ゲート: Planで合意したDo群が完了したら、Doの最後で「Checkフェーズに入ります」と明示宣言して停止（暗黙終了しない／Do群が残るなら宣言しない＝早閉じしない）。人間の承認なしに Action（ダイジェスト確定・git commit・cycle_complete）を実行しない。※セットアップ・初期化（init）はCYCLE番号を持たず、ダイジェスト/承認ゲートの対象外（実作業はCYCLE1から）。
- 方針ファースト: すぐ手を動かさず、まず方針と全体像を整理してから着手する。
- 品質: 不明点は推測せず確認。推測する場合は「推測ですが」と明記。成果物は常にファイルに残す。
- 認知負荷: 一度に扱う論点は7±2に制限。超えたらグループ化。
> 詳細プロトコルは Skill `cyclegen-cycle` を参照。本セクションは init スキルが正本（remind-primer.sh）から生成。手編集せず、文言変更時は再initで同期する。
```

## CYCLE開始チェックリスト（層2に薄く置く・memory_search必須化）

利用者 `CLAUDE.md` / `AGENTS.md`（層2）には、常時規律とは**別に**「CYCLE開始チェックリスト」を置く。目的は、どのモデル/ツールでも**CYCLE開始時に `memory_search` が確実に実行される**こと（In-Context Adaptation＝記憶再注入の本体を、Skill本文・開始リマインドhookに加えて**層2の静的ファイルでも担保**する多重防御）。

> **正本（single source）= Skill `cyclegen-cycle` の Plan フロー**（常時規律の正本 `remind-primer.sh` とは**別系統**）。
> 理由: `memory_search` はCYCLE開始専用であり、毎ターン注入される常時primer（案B 4ブロック）には意図的に含めない（FR034 F1 §7）。よって開始チェックリストの正本はPlanフロー側に置き、層2はその要点を薄く写す。

生成する「CYCLE開始チェックリスト」（Planフローの要点）:

```
## CYCLE開始チェックリスト（毎CYCLE、最初に必ず行う）
1. memory_search を実行し、関連する過去の記憶を再注入する。結果の reason を利用者に伝えてから進む。**利用者の指示が具体的でも省略しない**（記憶検索は意図の明確さと無関係に必要。飛ばすと成果物が過去の知見を欠いて平板化する）。関連記憶が薄い新テーマでも「関連なし」を確認してから進む。記憶ストア（MCP）未接続ならその旨を明示して続行。
2. 目的・成果物を確認し、工数を Nサイクル（約N×60分）で見積もる。
3. 利用者と合意してから着手する。
> 詳細は Skill `cyclegen-cycle` の Plan フローを参照。本セクションはその要点。文言変更時は再initで同期する。
```

## 層2テンプレート（利用者 CLAUDE.md / AGENTS.md の骨格）

上記「常時規律」に加え、以下のセクションを持つ薄いファイルを生成する（プロジェクト固有の中身は利用者が埋める）:

```
# {{PROJECT_NAME}} — CycleGenプロジェクト

## 人格・会話ルール
- AI: {{AI_NAME}} ／ 利用者: {{USER_NAME}}
- 応答言語: （日本語 / 英語）
- トーン: （簡潔・実務的 など）

## プロジェクト目的・スコープ
- 目的: （ここに記述）
- スコープ外: （ここに記述）

（↑ §層2の派生生成 で示した「常時規律」4ブロックをここに挿入）

（↑ §CYCLE開始チェックリスト で示した「CYCLE開始チェックリスト」をここに挿入）

## プロジェクト状態（毎CYCLE更新）
- フェーズ:
- 現在のCYCLE:
- 最終更新:
```

> Codex 等 `AGENTS.md` を使うツールでは、ファイル名を `AGENTS.md` にする以外は同一本文でよい（層2は共通ペイロード）。スラッシュコマンド非対応ツールでは「`/cyclegen` 相当の操作は自然言語で依頼」と1行添える（劣化運用）。
