# スキル・記憶ストア 運用知識

> MCP接続時のみ有効。記憶操作ツール（memory_*）の挙動そのものは各ツールのdescriptionに記載済み。
> この Skill には**MCPスキーマに無い判断基準**（Layer/Context/書き方）だけを置く。

## 記憶の詳しさのレベル（Layer）— store時に付与
記憶**そのものの抽象度**で判断する（今のセッションの作業内容ではない）。

| Layer | 名前 | 内容 | 例 |
|-------|------|------|-----|
| L1 | 個別タスク | 特定タスク・操作の記録 | 「Dockerfile.paasを作成した」 |
| L2 | プロジェクト知識 | プロジェクト固有の構造・仕様 | 「CycleGenは3層アーキテクチャ」 |
| L3 | 技術知識 | 再利用可能な技術的知見 | 「FastEmbedは…MiniLM-L12-v2が最適」 |
| L4 | 設計判断・洞察 | 判断の根拠・発見した原則 | 「Priority軸は利用増進モデルが正しい」 |
| L5 | メタ認知・思考パターン | 思考の型・仕事の進め方 | 「既存資産を新課題に接続するパターン」 |

## 作業の種類（Context）— store時に付与（確信がなければ省略可・自動判定される）
**記憶の内容が属する作業の種類**で判断する（今のセッションの作業種類ではない）。定義済みの9種:

| Context | 意味 |
|---------|------|
| **planning** | 計画策定・設計方針・アーキテクチャ |
| **implementation** | コード実装・機能開発・テスト |
| **debugging** | バグ調査・エラー解析・修正 |
| **review** | レビュー・品質検証・完了判定 |
| **learning** | 学習・調査結果・理解の記録 |
| **documentation** | ドキュメント作成・更新 |
| **operations** | 運用・デプロイ・環境構築 |
| **research** | 市場調査・技術調査・比較分析 |
| **strategy** | 事業戦略・方針決定・計画策定 |

未定義のContextを指定すると警告が返り自動判定に切り替わる。確信がなければ省略してよい。

## 重要度（Priority）
store時は**指定不要**（0.5で自動設定）。利用されるほど自動上昇（boost +0.10 / mark_used +0.05）。

## よい記憶の書き方
- **意味単位で分ける**: 1記憶に複数話題を混ぜない
- **検索で見つかる表現を使う**: 将来探すときに使う言葉を含める
- **結論を先に書く**: 「〜と判断した。理由は〜」
- **1件あたり3-10行**: 短すぎると文脈喪失、長すぎると検索精度低下

## トリガー語 → ツール対応
| 利用者の言葉 | ツール |
|------------|--------|
| 「覚えておいて」「記録して」 | `memory_store`（Layer/Context付与） |
| 検索結果が役立った | `memory_boost` |
| 検索結果が不適切 | `memory_dismiss` |
| 実際に参照・活用した | `memory_mark_used` |
| 「重要」「忘れないで」 | `memory_pin` |
| 「いらない」「もう使わない」 | `memory_archive` |

## CYCLE開始時の文脈注入（規律はhookが毎ターン注入）
1. 利用者の意図を待つ（記憶検索は意図が伝わるまで行わない）
2. 意図に基づき `memory_search` を呼ぶ
3. 検索結果の `reason`（なぜ返されたか）を利用者に伝えてから作業開始
