# CycleGen フロントドア（明示起動ルーター）

> このスキルは **明示起動専用**。AIが自動で起動してはならない。
> 利用者が明示指定で呼ぶ（Claude Code: `/cyclegen-core:cyclegen <arg>` ／ Codex: `$cyclegen <arg>`）。
> 自動起動の判断は各スキルの description が担う（cyclegen-cycle / cyclegen-memory / cyclegen-glossary / cyclegen-ops / onboarding）。本スキルは**自動起動が外したときの安全網**＋**思考モードの明示指定の受け皿**。

## 役割
`$ARGUMENTS` の **第1トークン**を解釈し、対応する動作へ薄く振り分ける。複雑な判断は各スキル本体に委ね、ここでは**ルーティングのみ**を行う。

## 分岐仕様

| 第1トークン | 動作 | 送り先 |
|------------|------|--------|
| `start` | CYCLE開始（工数のNサイクル見積→Plan合意→`memory_search`で文脈注入） | Skill `cyclegen-cycle` のPlan/Doフロー |
| `finish` | CYCLE完了処理（Do締め→Check宣言で停止→承認後Action） | Skill `cyclegen-cycle` の完了フロー |
| `memory` | 記憶操作の判断基準（Layer/Context判定・store/boost/pin等）を参照 | Skill `cyclegen-memory` |
| `onboard` | **初回のガイド付きオンボーディング**（サイクル0＝CYCLE0.1〜0.3）を開始／リセット後に再開する | Skill `onboarding` |
| `mode <x>` | **思考モードを明示指定**し、対応する強化プロンプトを1つ返す（下表） | 本スキル §思考モード表 |
| （引数なし） | 5分岐の使い方を1行ずつ案内して終了 | — |

ルーティング手順:
1. `$ARGUMENTS` の第1トークンを取り出す。
2. `start` / `finish` / `memory` / `onboard` のいずれかなら、対応スキルの該当フローを実行する（そのスキルを名指し起動してよい）。
3. `mode` なら、第2トークン `<x>` を §思考モード表 の行に最も近いものへ意味マッチさせ、その**サジェスト文を1つだけ**返す。
4. 引数が無い／未知のトークンなら、上表の使い方を簡潔に案内する。

## 思考モード表（`mode <x>` の中身）

利用者が思考モードを**明示指定**したとき、その意図に最も近い行のサジェスト文を1つ返す。
（旧 `cyclegen-prompts` の自動検知サジェストを、誤爆を避けるため明示指定へ移し替えたもの。正本: `~/.claude/CLAUDE.md` プロンプトサジェスト節 ／ `docs/design/CYCLE12.9.2_cyclegen-ops改訂案.md`）

| mode `<x>`（例） | 利用者の意図 | 返すサジェスト文 |
|------------------|------------|-----------------|
| `analyze` / 調査 | 調べる・比較する・分析する | 本質的な価値と課題を多角的に考察し、整理統合して提案してください |
| `review` / レビュー | 評価する・チェックする | 攻め（機会）と守り（リスク）の両面から検討してください |
| `review-deep` / 深掘り | もっと厳しく・穴はないか | 顧客・投資家・競合それぞれの視点から評価してください |
| `review-precision` / 精度 | これは確かか・根拠は | 確信度が高い部分と推測を区別して示してください |
| `decide` / 意思決定 | 決めたい・どちらがよいか | 意思決定に使えるフレームワークとして再構成してください |
| `create` / 発散 | アイデア・他にないか・ブレスト | 異なる業界に適用したら？ 3つのシナリオを想像してください |
| `create-bold` / 飛躍 | もっと攻めて | 常識的な答えの先にある、意外だが筋の通る提案をしてください |
| `create-structural` / 原理 | 原理から考える | この課題を自然科学の法則のアナロジーで分析してください |
| `root-cause` / 根本原因 | なぜ・原因は・何が問題か | 最も重要な1点に絞って深く掘り下げてください |
| `stuck` / 行き詰まり | うーん・難しい・詰まった | 最大の制約がなかったら？ → その理想に近づく第一歩は？ |
| `write` / 文書 | 書いて・ドラフト・資料 | 以下の条件を満たして提案してください: (条件1)(条件2)(条件3) |
| `clarify` / 曖昧 | 指示が不明確 | より良い回答のために必要な追加情報があれば、まず質問してください |

> 一覧にない mode が指定されたら、最も近い行を選んで返すか、該当が無ければ上表のmode一覧を案内する。
